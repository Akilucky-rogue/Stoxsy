## Layout facts (M1, from the real file of 2026-10-30; structure and counts only, no AMFI values)
- One sheet, `TER_Revised`; header on row 1; no banner rows above it. The file ends with a **disclaimer block** (a blank row, "Disclaimer :", numbered notes) that must not be read as data: 13 rows with no date.
- 15 columns: `NSDL Scheme Code`, `Scheme Name`, `Scheme Type`, `Scheme Category`, `TER Date`, then for **Regular Plan** and again for **Direct Plan**: Base Expense Ratio (BER), Brokerage cost, Transaction Cost, Statutory Levies (including GST), Total TER (all `(%)`).
- **No AMC column, no ISIN, no AMFI numeric scheme code.** The scheme identifier is the NSDL scheme code (text, a structured string with `/` separators); one code is published in two spellings (a trailing `?`), and many codes contain a stray space, so codes must be normalised (strip whitespace and a trailing `?`).
- All numeric cells are stored as **text** (e.g. "1.78"). `TER Date` is a real date.
- **Daily granularity:** one row per scheme per day (29 days, 1 to 29 Oct 2026), 58,095 data rows, 2,174 distinct scheme codes, 2,170 distinct normalised names, no duplicate (code, date). Rows per day vary (about 1,800 to 2,160); the last day (29 Oct) is **partial** (1,027 rows), consistent with a mid-day download. 785 schemes appear on all 29 days; the rest launched or reported part-way. TER changed within the month for 725 schemes.
- Scheme Type: Open Ended / Close Ended / Interval Fund. Scheme Category: 96 distinct values.
- **Integrity:** Total TER equals BER + brokerage + transaction + statutory on every row (max difference 0.00). A value of 0 for a whole plan means "plan not offered" (regular total 0 on 3,113 rows, direct total 0 on 6,709 rows, never both).
- **Published data contains implausible values**: total TER above 3 on 2,072 regular-plan rows (79 schemes) and 341 direct-plan rows (13 schemes), above 5 on 273 and 150 rows, with statutory levies the usual culprit. Direct total is not below regular total on 140 rows. These are published as such; they are flagged, never silently corrected.
- One scheme code appears under two spellings of the same name (case only).
- **Join feasibility (read-only check against `mf_scheme_master`)**: with plan and option words stripped from names, 2,174 of 2,174 TER scheme codes match a master name key, no key spans more than one AMC, and 8,700 of 8,772 active master schemes (99.2%) would receive a TER (the 72 without: 48 debt, 20 equity, 4 other, to be explained at M5). One TER scheme maps to about 4 master rows (median, up to 36: growth and IDCW options, each plan).

### Consequences for the spec (to be decided at M2)
Daily rows, not monthly; the source key is the NSDL code, not the AMFI numeric scheme code, so storage is keyed by the normalised NSDL code with a separate mapping to `scheme_code`; both plans sit on one source row; the footer must be skipped; the "reject the file above 5%" rule is wrong for real data (row-level flags instead); zero means "not offered" (store as missing); the latest day of a file may be partial.
